# n8n — self-hosted, Docker

Runs ARAK Content Studio's n8n instance in its own container, separate from
any other n8n on this machine (the Lighting project's `lighting-n8n-1`
binds host port 5678 — this one uses **5680**, its own container name
(`arak-marketing-n8n`), and its own named volume, so starting/stopping/
rebuilding this one never touches that one or anything else running).

## First-time setup

```bash
cd n8n/docker
cp .env.example .env
# fill in real values in .env: ANTHROPIC_API_KEY, REPLICATE_API_TOKEN,
# SUPABASE_KEY (service role, not anon), FAL_KEY
docker compose up -d
```

n8n is now at http://localhost:5680.

## Importing workflows

The workflow JSON in `../workflows/` is the source of truth (generated by
`../gen_workflows.py` — never hand-edit the JSON). After regenerating it,
re-import:

```bash
docker exec arak-marketing-n8n n8n import:workflow --separate --input=/workflows
```

Then publish (activate) each one so its webhook actually listens, and
restart for the activation to take effect:

```bash
docker exec arak-marketing-n8n n8n list:workflow          # get each id
docker exec arak-marketing-n8n n8n publish:workflow --id=<id>   # repeat per workflow
docker compose restart n8n
```

## Pointing the app at it

In the app's Settings → Integrations, each webhook URL is
`http://localhost:5680/webhook/<path>` — the path matches the workflow's
webhook node (e.g. `arak-draft-copy`, `arak-caption-studio`). If the app
and n8n aren't on the same machine later (real deployment), swap
`localhost:5680` for wherever this container ends up running — nothing
else about the setup changes.

## Updating secrets

Edit `.env`, then `docker compose restart n8n` — env var changes only
take effect on restart, not live.

## Stopping / removing

```bash
docker compose down          # stops + removes the container, keeps the volume (workflows/credentials survive)
docker compose down -v       # also deletes the volume — full reset
```
